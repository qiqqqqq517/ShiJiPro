## 1. 回归方法

自动化脚本 `tools/shiji_smoke_test.py`（Python 3.12 + adb，无第三方依赖）：

| 能力 | 实现 |
|---|---|
| 装机 / 授权 | `adb install -r -t -g`；MIUI 权限弹窗按 **UI XML 包名**（`com.lbe.security.miui`）识别并点「使用期间允许」，不依赖 `mCurrentFocus` 文案 |
| 页面走查 | 每页从顶部**慢速拖拽（1200ms，屏高 44%）滚动到底**，逐帧 `uiautomator dump` 聚合 `text` 与 `content-desc` |
| 字段判定 | `ValueRow` 用 `clearAndSetSemantics` 合并语义，字段名只出现在 `content-desc`，故两者都要采集 |
| 标签导航 | 393dp 宽度下顶部标签行仅显示前 4 个；脚本会横向拖动标签行查找「设备 / 覆盖测试 / 测速」 |
| 交互覆盖 | 3 个覆盖层（双卡对比 / 日志中心 / 设置）+ 系统返回键、端点录入对话框、连点「刷新」×3、刷新后字段回归 |
| 崩溃取证 | `logcat -d` 全文落盘，断言无 `FATAL EXCEPTION` / `ANR in com.shiji.pro` |

判定口径：断言的是**卡片标题 + 每张卡首行字段**。全量字段清单（如服务小区 39 个键）由代码内固定列表保证；
UI 侧验证「每张卡片与首行在真机上确实渲染、N/A 占位可见」，不把首屏观感当作数据正确性结论。

## 3. 本轮发现与修复

| 类型 | 问题 | 处理 |
|---|---|---|
| 真机 UI 缺陷 | 窄屏顶栏动作行末尾的「更新 HH:mm:ss」被右侧裁切，且与状态条「数据已就绪（…）」重复 | 移除该冗余文本（`MainActivity.kt`），保留状态条时间 |
| 测试脚本缺陷 1 | 快速 `input swipe` 触发 fling，一次滚过整张卡片，导致「内存与存储」等被跳过 | 改慢速拖拽 1200ms + 屏高 44% 步长，保证相邻帧重叠 |
| 测试脚本缺陷 2 | 标签行在 393dp 下只显示前 4 个，直接 `find` 找不到「设备/覆盖测试/测速」 | 增加标签行横向拖动查找 `tap_tab()` |
| 测试脚本缺陷 3 | MIUI 权限弹窗包名为 `com.lbe.security.miui`，`mCurrentFocus` 行会被窗口标题污染 | 改为解析 UI XML 的 `package` 属性判定，并点最靠下的允许按钮 |
| 测试脚本缺陷 4 | 早停用「文本集合」比较，顶栏秒级时间戳每次都变 → 永远不早停，单页跑满 12 轮 | 早停改用**布局坐标集合**比较 |

本轮**未发现**崩溃、ANR、字段丢失、布局重叠或点击无响应。

## 4. 仍未覆盖 / 边界

1. WiFi「已连接」分支：本轮设备 WiFi 未连接，仅验证了未连接态的 N/A 与说明；已连接分支仍只有单测覆盖。
2. GNSS 原始观测：机型 HAL 不输出 `GnssMeasurement`，界面如实 N/A；室内未锁定，DOP 等派生值不可验。
3. 大屏（≥600dp / ≥840dp）分支：仅代码级与布局单测覆盖，未在平板/折叠屏实机走查。
4. 深色主题：真机默认浅色；深色仅由主题令牌保证，未做逐页截图对比。
5. 存储仍为内存态，进程重启后设置与快照不保留。
